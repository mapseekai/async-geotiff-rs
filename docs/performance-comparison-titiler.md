# async-geotiff-rs 与 TiTiler 大型 COG 性能对比

## 1. 测试环境

| 项目 | 配置 |
|---|---|
| 机器 | Mac mini，Apple M4 |
| CPU | 10 核：4 个性能核、6 个能效核 |
| 内存 | 16 GB |
| 操作系统 | macOS 15.6.1，ARM64 |
| async-geotiff-rs | v0.11.0 本地工作区源码，release 构建；Rust 1.92.0 |
| TiTiler | 2.4.0；Uvicorn 0.53.0，单 worker |
| Python / Rasterio / GDAL | 3.12.9 / 1.5.1 / 3.12.4 |
| rio-tiler | 9.4.6 |
| 浏览器 | Chromium 153.0.8010.53，无头模式 |
| 数据访问 | 同一台机器、同一份 `data/` 文件、同一个本地 HTTP Range 数据服务 |

两套渲染服务交替运行，每次只运行一个渲染服务进程，保留各自默认的内部线程并行度。Rust 使用 512 MiB 解码块缓存和 512 MiB 工作内存预算。TiTiler 设置 `GDAL_CACHEMAX=512`、`GDAL_DISABLE_READDIR_ON_OPEN=EMPTY_DIR`、`GDAL_HTTP_MERGE_CONSECUTIVE_RANGES=YES`、`GDAL_HTTP_TIMEOUT=20`。这些配置不代表两者的进程总内存上限相同。

## 3. 测试口径

两边均请求 `WebMercatorQuad` 网格下的 **256×256 PNG**，选择波段 1、2、3，读取和重投影重采样都为 `nearest`。每份数据在两边使用相同的显式拉伸区间，避免自动统计与样式差异影响对比；两边保留各自默认 PNG 编码策略。

**首次**：每对测试前重新启动渲染进程，待端口就绪后发出该数据的第一次瓦片请求；包含按需打开数据和生成瓦片的时间，不包含进程启动时间。**二次**：在同一进程内重复相同坐标及参数，保留服务端缓存，但禁用客户端响应缓存。macOS 文件缓存未清空，因此首次指应用层冷请求，不指完全冷磁盘读取。

| 场景 | 请求规模 | 计时终点 | 重复次数 |
|---|---|---|---|
| 单瓦片 | 单并发，数据中心附近的一张详细级别瓦片 | 完整收到 PNG 响应 | 每份数据、每个服务 10 对首次／二次 |
| 浏览器视口 | 4×4 共 16 张相邻瓦片，最大并发 6 | 最后一张 PNG 完成 `createImageBitmap` 解码 | 每份数据、每个服务、每个级别 5 对 |
| 并发批次 | 8×4 共 32 张相邻且不同的瓦片，32 并发 | 完整收到全部 HTTP 响应 | 每份数据、每个服务 5 对 |

下表耗时均为各轮次的**中位数**，越小越快。视口和并发批次记录的是整批完成时间，不是单瓦片平均耗时。请求均落在数据有效覆盖区，不将空白或失败响应视为加载成功。浏览器缓存关闭，二次视口仍向后端发出 16 次网络请求。

## 7. 成功率与图像校验

| 场景 | Rust 成功／请求数 | TiTiler 成功／请求数 |
|---|---:|---:|
| 单瓦片 | 100/100 | 100/100 |
| 浏览器视口（两种级别） | 1600/1600 | 1600/1600 |
| 32 并发批次 | 1600/1600 | 1600/1600 |
| **合计** | **3300/3300** | **3300/3300** |

成功响应均校验为 256×256 PNG 且包含非透明像素。单瓦片及 32 并发批次中，同一服务、同一坐标的首次／二次及重复轮次输出像素哈希一致。浏览器场景每次均检查全部 16 张瓦片的可见性，并核对网络请求数。

## 9. 结果范围

单瓦片请求中，TiTiler / Rust 耗时比：首次 **4.96～14.10×**，二次 **5.67～24.66×**。该范围来自上表各数据的中位数比值，不是所有请求合并后的总体加速比。

浏览器 16 瓦片加载中，TiTiler / Rust 耗时比：首次 **7.29～20.68×**，二次 **10.57～33.56×**。该范围来自上表各数据的中位数比值，不是所有请求合并后的总体加速比。

32 并发批次中，TiTiler / Rust 耗时比：首次 **6.35～41.50×**，二次 **8.50～86.06×**。该范围来自上表各数据的中位数比值，不是所有请求合并后的总体加速比。

结果对应本机环回网络、单渲染进程、指定数据和参数下的完整服务表现；未对桌面其他进程做隔离。Rust 的 PNG 响应体积更大；本次未测试限速公网、多 worker 部署、整幅 TIFF 下载、持续满载吞吐量或地图绘制帧率，不能将本表耗时直接等同于这些场景。
