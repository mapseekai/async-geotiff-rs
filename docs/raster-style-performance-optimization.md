# Raster Style RGB 性能退化分析与优化

前半部分保留历史优化记录；最新结果见文末“RGB 分块遍历与原生整数后续优化”，之前的浮点量化与 D1 nearest 修复记录均保留。

## MAP-244 的含义

MAP-244 的原问题是 Raster Style 迁移后 RGB 渲染失去类型专用快路径：重复执行表达式、提升整幅源图为 F64，并对每个波段重复计算 warp 几何。此前已经恢复 UInt8/UInt16 LUT、共享几何、独立 NoData，并优化浮点缩放、统计样本和分块计算。该 issue 保留打开，用于跟踪残余浮点 RGB 和端到端性能差距；旧描述中的耗时是不同阶段的历史测量，不能当成当前实测。

## 本次确认的开销与改动

1. SDK 首次解析时懒加载 Q2 参数表并编译内置 JSON Schema。五个全新进程的阶段日志中，D2～D5 首次 parse 为 2.38～2.68 ms，后续请求为 0.06～0.10 ms；D1 的首轮为 6.27 ms。`AppState::new` 现在用内置合法 Q2 样式预热，修改后 D2～D5 首次 parse 为 0.05～0.07 ms、D1 为 0.14 ms。初始化移到启动阶段，校验仍完整执行；这降低首请求延迟，不代表减少了初始化总工作。

2. `warp_dependencies` 对同投影、nearest、无 NoData 的 UInt8/UInt16 输入，即使使用全部源波段，也会先 `select` 复制数据和掩膜。现在完整依赖集合直接复用源图进入现有 warp；子集仍先选择，跨投影、有 NoData 和其他类型保持原路径。合成 U8 微基准中，1024² 源图缩到 256² 的 copy+warp 约 710 us，借用源图约 59 us；512² 分别约 74 和 61 us。该微基准不等同于真实 HTTP 收益。

只增加两个生产分支（初始化调用及完整波段判定），没有新增依赖或缓存，没有改变像素量化、拉伸、统计精度、PNG 编码或内存预算。

## 结果与剩余边界

首次单瓦片耗时降低 13～34%，首次浏览器视口降低 3～15%，首次 32 并发批次降低 3～26%。热请求没有普遍提升：D4 详细视口二次为 10.20 → 10.50 ms（+2.9%）；D1 热单瓦片为 1.81 → 2.09 ms（+15.2%，约 +0.28 ms），这条跨投影路径不执行新增的完整波段分支，原因尚未确认，仍需跟踪。不得声称全部退化已经消除，也不能用本轮 D4 的 25.20 ms 直接对上次非配对的 41.90 ms 宣称收益。

单瓦片及并发批次的所有匹配坐标、首次／二次和重复轮次的解码像素哈希一致；五个中心 PNG 压缩字节完全一致。浏览器全部请求均为 256²、可见且禁用客户端缓存；响应大小完全不变。新增单元测试覆盖 UInt8/UInt16、通道重排、掩膜及边界输出，与原选择复制路径一致。

## D1 热请求后续优化（2026-09-30）

本节是上述首轮优化之后的追加验证。before 为已包含 SDK 预热与完整波段借用的版本，after 仅追加 `src/warp/reproject.rs` 的原生整数 nearest 采样。此前的 +0.28 ms 记录保留为历史结果，不能当作当前状态。

### 复现与原因

先用首轮优化前／后的原始二进制重新交替测试 30 轮，每个进程连续请求同一 D1 瓦片 22 次。二次请求为 3.090 → 2.625 ms（-15.1%），其按进程配对 bootstrap 95% 区间为 -42.7%～+61.9%；第 3～22 次的连续热请求为 1.731 → 1.771 ms（+2.4%），按每进程中位数 bootstrap 区间为 -0.7%～+5.2%。原 +15% 没有稳定复现，不能归因于首轮补丁；新进程二次请求波动尤其大。本机未隔离，这些区间只描述本轮样本。

当前 D1 为 UInt16、EPSG:32651、NoData=0，走跨投影选定波段的标量采样。独立阶段日志显示，热请求主要成本在 fused CPU，而非读取。原路径逐波段构造源尺寸 F64 与数值掩码，再构造 F64 目标并转回原类型；nearest 只需要读取一个原生像素，这些中间数据不必要。

现在仅对选定波段的 UInt8/UInt16 nearest 使用借用数组直接采样，在采样点检查源掩码和该波段 NoData，并保留共同输出有效性。沿用原坐标网格、半像素边界、夹取与舍入；无效值填充仍按原类型转换。浮点、宽整数及插值核继续原路径；没有新增依赖、缓存或 unsafe，也未更改渲染量化、PNG 编码和容量限制。

## 浮点量化与插值复核（2026-09-30）

此次继续排查 MAP-244 未覆盖的直接 RGB 渲染和双线性路径。before 包含上节全部修复，after 只修改 `src/style/raster.rs` 的 `range_byte`、`rgb_array` 及已有量化边界测试，未改 warp、PNG 编码、线程策略或 SDK 校验。TiTiler 未在本轮重新运行，正式 TiTiler 比较原记录保留。

### 保留的最小改动

浮点范围量化仍逐通道执行缩放和舍入。现在在瓦片外预计算 `255 / span`，减少逐像素乘法，并利用非负区间中整数转换的截断行为省去重复 `floor`。对于三个通道均为 0～255 的常见范围，给同一个量化函数传入固定参数，使编译器能消除恒定的范围检查。近半字节边界仍回退原始除法与 1e-10 tie tolerance；极端／退化范围、非有限值、掩膜、NoData、透明范围和 opacity 沿用原语义。

独立算术探针显示固定范围能减少量化开销，随后以完整 render+PNG 和真实 HTTP 验证收益。另试过将并行门槛从 256² 提高到 512²，但 256² F64 变慢，因此撤回；没有保留推测性的线程调整，没有新增依赖、缓存或 unsafe。

## RGB 分块遍历与原生整数后续优化（2026-09-30）

before 是上一节浮点优化后的版本，after 追加本轮 `rgb_array` 最小循环优化；之前各阶段的绝对耗时保留为历史，不跨轮混用来计算收益。原 TiTiler 正式结果未改动，本轮仅复测 Rust 两版与原始 legacy。

### 改动与诊断

先用相同 RGBA 测独立 PNG 编码，并与完整 render+PNG 比较。256² 独立编码约 0.19～0.20 ms，未显示与完整 RGB 渲染相同的退化，故把优化集中在像素遍历；这不是可以直接相减的精确阶段耗时，编码输入缓存状态与完整路径不同。本轮未改 PNG 编码器或参数。

1. 每个输出块先借用三个等长通道切片，通过 `zip` 与 RGBA 一起遍历，减少逐像素全局索引检查；不复制源图，不增加中间数组。
2. 对 LUT 对应的原生 UInt8/UInt16、无 NoData、非透明范围裁剪输入，提前进入简单循环。原生整数本身有限，因此不再逐像素重复有限值与 NoData 检查；仍检查源掩膜并沿用 opacity。
3. 三个通道范围均为 0～255 时，原生整数直接转换为字节，省掉 LUT 查表；UInt16 超过 255 仍按现有行为饱和。带 NoData／透明范围／浮点输入保持完整原检查与量化路径。

无新 public API、依赖、缓存、unsafe 或线程策略。扩展已有 257² 分块尾部对照测试，增加 UInt8/UInt16 与表达式渲染器比较，包含掩膜、NoData、透明范围、重复通道与半透明度。

### 30 对进程的 release 渲染验证

沿用上一节的三波段合成输入、范围和 release 配置；每版 30 个进程按轮次交替，每次先预热 10 次，再在 256²／1024² 测 200／20 次 render+PNG。同一 executable 还测 linked legacy 和相同 RGBA 的独立编码，固定内部顺序；外层补丁版本交替。下表为每进程均值再取中位数，bootstrap 按进程配对，10,000 次、seed=244。

| 类型／尺寸 | before → after（ms） | 变化 | 配对 95% 区间 |
|---|---:|---:|---:|
| u8 / 256² | 0.269 → 0.250 | -6.9% | -8.6%～-5.2% |
| u16 / 256² | 0.268 → 0.265 | -1.1% | -1.9%～+2.1% |
| f64 / 256² | 0.332 → 0.325 | -2.0% | -3.1%～-1.0% |
| u8 / 1024² | 4.957 → 4.854 | -2.1% | -6.8%～+0.6% |
| u16 / 1024² | 5.034 → 5.256 | +4.4% | -1.4%～+7.6% |
| f64 / 1024² | 4.692 → 4.835 | +3.0% | -0.6%～+6.1% |

UInt8 256² 确认改善 **6.9%**，F64 256² 确认改善 **2.0%**；其他四行区间跨零，不声称稳定改善。尤其 UInt16/F64 1024² 中位数 +4.4%／+3.0%，暂未确认为代码退化，不能声称所有尺寸提升。独立编码对照中这两组相同源码也出现约 +5.2%／+3.4% 的时间漂移，说明桌面与缓存噪声仍明显；不把其简单相减作为修正后的收益。

每 after 进程的 current/linked-legacy 比值再取中位数：UInt8 256² 为 +1.2%（95% -1.0%～+3.4%），1024² 为 +2.6%（-0.9%～+7.6%），此前可复现的约 6%～9% **直接 UInt8 渲染差距本轮不再显著**。F64 256² 仍为 +8.0%（+6.3%～+10.2%，本轮绝对中位数 0.325 vs 0.303 ms）；F64 1024² 比 legacy 快约 12.2%。UInt16 两尺寸比 legacy 快约 6.9%／5.0%。剩余浮点差距不能通过恢复 legacy 截断或降低校验消除。
