# async-geotiff-rs 与 TiTiler 大型 COG 性能对比

第 1～10 节保留优化前的正式复跑记录；随后多轮性能优化及交替配对复测见 [Raster Style 性能优化报告](raster-style-performance-optimization.md)。

复跑日期：2026-09-30（Asia/Shanghai）。当前 Raster Style 渲染仍在全部测试项中快于 TiTiler；数值范围已更新，UInt16 像素量化不再与 TiTiler 完全一致，见第 10 节。

| 数据访问 | 同一台机器、同一份 `data/` 文件、同一个本地 HTTP Range 数据服务 |

两套渲染服务交替运行，每次只运行一个渲染服务进程，保留各自默认的内部线程并行度。Rust 使用 512 MiB 解码块缓存和 512 MiB 工作内存预算。TiTiler 设置 `GDAL_CACHEMAX=512`、`GDAL_DISABLE_READDIR_ON_OPEN=EMPTY_DIR`、`GDAL_HTTP_MERGE_CONSECUTIVE_RANGES=YES`、`GDAL_HTTP_TIMEOUT=20`。这些配置不代表两者的进程总内存上限相同。

## 3. 测试口径

两边均请求 `WebMercatorQuad` 网格下的 **256×256 PNG**，选择波段 1、2、3，读取和重投影重采样都为 `nearest`。每份数据在两边使用相同的显式拉伸区间，避免自动统计与样式差异影响对比；两边保留各自默认 PNG 编码策略。Rust 使用 Q2 的 `version=2.0&type=rgb&method=linear`，TiTiler 保留原有参数；重复 `bidx` / `rescale`、`tilesize=256`、`resampling=nearest`、`reproject=nearest` 均不变。

**首次**：每对测试前重新启动渲染进程，待端口就绪后发出该数据的第一次瓦片请求；包含按需打开数据和生成瓦片的时间，不包含进程启动时间。**二次**：在同一进程内重复相同坐标及参数，保留服务端缓存，但禁用客户端响应缓存。macOS 文件缓存未清空，因此首次指应用层冷请求，不指完全冷磁盘读取。

| 场景 | 请求规模 | 计时终点 | 重复次数 |
|---|---|---|---|
| 单瓦片 | 单并发，数据中心附近的一张详细级别瓦片 | 完整收到 PNG 响应 | 每份数据、每个服务 10 对首次／二次 |
| 浏览器视口 | 4×4 共 16 张相邻瓦片，最大并发 6 | 最后一张 PNG 完成 `createImageBitmap` 解码 | 每份数据、每个服务、每个级别 5 对 |
| 并发批次 | 8×4 共 32 张相邻且不同的瓦片，32 并发 | 完整收到全部 HTTP 响应 | 每份数据、每个服务 5 对 |

下表耗时均为各轮次的**中位数**，越小越快。视口和并发批次记录的是整批完成时间，不是单瓦片平均耗时。请求均落在数据有效覆盖区，不将空白或失败响应视为加载成功。浏览器缓存关闭，二次视口仍向后端发出 16 次网络请求。

## 9. 结果范围

单瓦片请求中，TiTiler / Rust 耗时比：首次 **4.84～12.07×**，二次 **6.53～26.95×**。该范围来自上表各数据的中位数比值，不是所有请求合并后的总体加速比。

浏览器 16 瓦片加载中，TiTiler / Rust 耗时比：首次 **7.76～17.09×**，二次 **12.57～31.76×**。该范围来自上表各数据的中位数比值，不是所有请求合并后的总体加速比。

32 并发批次中，TiTiler / Rust 耗时比：首次 **7.59～36.05×**，二次 **13.05～80.32×**。该范围来自上表各数据的中位数比值，不是所有请求合并后的总体加速比。

结果对应本机环回网络、单渲染进程、指定数据和参数下的完整服务表现；未对桌面其他进程做隔离。Rust 的 PNG 响应体积更大；本次未测试限速公网、多 worker 部署、整幅 TIFF 下载、持续满载吞吐量或地图绘制帧率，不能将本表耗时直接等同于这些场景。

## 10. Raster Style 是否实质改变对比

性能优势的结论没有逆转：当前版本在 40 项匹配的数据／级别／首次或二次请求中均快于 TiTiler，两个服务均为 3300/3300 成功，响应尺寸与旧结果一致。但不能沿用旧的耗时倍数或把此次结果解释为完全无性能变化。

除更新原有完整测试外，还使用原测试保留的 Rust 二进制进行同日完整对照：SHA-256 `2feb3eb28025b731085c0e0b5261883ccb31cf57a56ffc6f5b931a643077464e` 与旧记录一致，使用原有 legacy 请求。对照的每个服务同样完成 3300/3300 请求，所有图像、缓存及重复像素校验通过。当前完整测试先运行，旧二进制对照随后运行；两轮均使用当前版本的同一个 Range 服务程序。旧二进制未由当前 HEAD 重建。

以下是同日对照与当前版本的 TiTiler / Rust 中位数耗时比范围（不是合并请求的总体速度）：

| 场景 | 阶段 | 同日旧二进制对照 | 当前 Raster Style |
|---|---|---:|---:|
| 单瓦片 | 首次 | 4.89～17.98× | 4.84～12.07× |
| 单瓦片 | 二次 | 5.96～28.23× | 6.53～26.95× |
| 浏览器 16 瓦片 | 首次 | 7.71～17.83× | 7.76～17.09× |
| 浏览器 16 瓦片 | 二次 | 11.73～34.28× | 12.57～31.76× |
| 32 并发 | 首次 | 6.70～38.77× | 7.59～36.05× |
| 32 并发 | 二次 | 9.64～86.37× | 13.05～80.32× |

匹配行的 Rust 绝对耗时变化如下；正值为当前版本更慢，负值为更快。每行列出各数据／级别的变化范围，不把 D1、D2 当作独立场景合并统计。

| 场景 | 阶段 | 当前相对同日旧二进制 |
|---|---|---:|
| 单瓦片 | 首次 | +6.4%～+54.9% |
| 单瓦片 | 二次 | -11.4%～+8.9% |
| 浏览器 16 瓦片 | 首次 | +3.3%～+64.3% |
| 浏览器 16 瓦片 | 二次 | -15.0%～+37.1% |
| 32 并发 | 首次 | -18.6%～+5.7% |
| 32 并发 | 二次 | -32.1%～+10.2% |

单项变化达到需要单独关注的幅度：D5 单瓦片首次由 6.45 ms 变为 10.00 ms（+54.9%）；D4 详细视口首次由 25.50 ms 变为 41.90 ms（+64.3%）；D4 详细视口二次由 9.70 ms 变为 13.30 ms（+37.1%）；D2 并发批次二次由 64.18 ms 变为 43.59 ms（-32.1%）。因此，本次渲染变化没有改变速度排名，但部分请求路径的绝对性能已有明显变化，不能报告为无影响。

上述变化是本机端到端实测，包含 Q2 解析、数据打开、渲染、编码和排队；两轮顺序运行，TiTiler 自身耗时也有变化。没有进行随机化版本配对、显著性检验或只替换渲染器的微基准，不能将差值全部归因于 Raster Style。未显式拉伸的默认 UInt16 显示、自动统计、其他渲染类型与重采样不在本次比较范围内。

像素兼容性结论有明确变化：同日中心瓦片对照中，TiTiler 五份数据的 RGBA 均与旧输出相同；Rust 的 D3～D5 仍完全相同，而 D1、D2 只有 RGB 通道出现 0 或 +1 的变化，掩膜完全相同。D2 原来与 TiTiler 完全一致，现在最大差为 1、平均差约 0.506；D1 平均差由 0.003866 增至约 0.485，P99 差为 1，原有重投影路径的最大差仍为 50。当前 `src/style/raster.rs` 的字节量化采用半步向上舍入，这与上述 +1 的变化吻合。视觉差异较小，但需要逐像素相等的使用方必须计入这一变化。

PNG 中心响应大小及 Rust / TiTiler 大小比与旧结果完全相同；本次没有消除 Rust 默认 PNG 更大的传输代价。
